## Frozen visual thesis

Mariage OS is **wedding editorial warmth × calm operating-system precision**.

The application is deliberately richer than a monochrome productivity tool, but its richness comes from a controlled color system, strong photography where useful, typography, hierarchy and polished motion — not from random decoration.

## Hard visual rules

- warm neutral application canvas;
- stable module-specific accent families;
- semantic colors remain separate from domain colors;
- one coherent component grammar across modules;
- no giant generic CRUD screens;
- no “one purple accent everywhere” theme;
- no arbitrary rainbow per screen;
- no UI generated by dumping schema fields into cards/tables;
- no image-heavy decoration on operational/financial screens;
- no critical state communicated by animation/color alone;
- major screen acceptance includes desktop/mobile visual evidence.

## Source precedence

If visual documents conflict:

1. accessibility/security/privacy requirements win;
2. `COLOR-SYSTEM.md` controls color tokens/roles;
3. `VISUAL-IDENTITY.md` controls brand personality;
4. `UX-ARCHITECTURE.md` controls page/workflow structure;
5. `DESIGN-SYSTEM.md` controls reusable component grammar;
6. `SCREEN-BLUEPRINTS.md` controls feature composition;
7. implementation-specific decisions may refine details only if the above remain true.

A developer may not replace the multi-color domain architecture with a simpler one-accent theme for convenience.
